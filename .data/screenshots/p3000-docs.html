VerifyOne API documentation

VerifyOne is the pre-action compliance gate for AI calling and messaging agents. One API call before every dial or send returns an auditable allow, review, or block decision — so your agent blocks risky contacts instead of creating liability. VerifyOne provides compliance controls and audit evidence; it does not provide legal advice or guarantee regulatory outcomes.

1. Quickstart

Call the pre-dial gate before placing an outbound call. Without an API key, requests are metered per IP (500 checks/month). Create an account for an API key and higher limits.

curl -X POST https://app.verifyone.io/api/v1/gate/phone \
  -H "Content-Type: application/json" \
  -d '{"phone":"+14155550123","channel":"voice"}'

Dial only on ALLOW. On DENY, log the reason and skip.

2. Authentication

Pass your key as a Bearer token or an x-api-key header. Keys are stored SHA-256 hashed and shown once at creation.

Authorization: Bearer vk_live_...
# or
x-api-key: vk_live_...

Create or rotate keys in the dashboard or via POST /api/auth/signup (returns the key once).

3. Pre-dial phone gate

POST /api/v1/gate/phone

{
  "phone": "+14155550123",          // required, E.164
  "channel": "voice",               // "voice" | "sms" (default voice)
  "consent": {                       // optional — what you have on file
    "declared": true,
    "type": "express_written"        // "express_written" | "ebr" | "none"
  },
  "profile": "ai_outbound_shield",   // default | "full_stack" adds live HLR
  "live_hlr": false                  // shortcut for profile full_stack
}

Related endpoints:

  • POST /api/v1/gate/batch — pre-screen a list (max 5,000 keyed / 200 keyless).
  • POST /api/v1/gate/email — pre-send gate for AI SDRs (send / hold / block).
  • POST /api/webhooks/vapi and /api/webhooks/retell — platform-native pre-call gates.

4. Decision values

VerifyOne's product contract is an allow | review | block decision with a reason and evidence ID. The live v1 API returns ALLOW | DENY — the mapping below shows how to interpret each response, and native review is on the roadmap. Until it ships, configure your agent to pause on specific reason codes instead of dialing.

Product contractLive v1 APIAgent behavior
allowALLOWAll enabled checks passed. Proceed and store the evidence_id.
review— (roadmap)Native review is planned. Today: configure your agent to pause on specific reasons (for example QUIET_HOURS or REASSIGNED_NUMBER) instead of dialing.
blockDENYDo not act. Log the reason and keep the evidence_id. Timeouts and unavailable sources also return DENY (fail-closed).

Live v1 response fields:

{
  "decision": "ALLOW" | "DENY",
  "reason": "PASS" | "LITIGATOR_TRAP" | "DNC_NATIONAL_VIOLATION" | ...,
  "evidence_id": "evt_...",        // tamper-evident audit record id
  "risk_score": 0-100,
  "checks": { "valid_number": true, "line_type": "mobile", "dnc": {...}, ... },
  "fresh_for_hours": 24            // re-check recommendation
}

Reason codes (v1):

PASSAll enabled checks cleared — decision is ALLOW.
ACTIVE_HLRLive HLR confirms the number is active (full_stack profile).
LITIGATOR_TRAPNumber matched the litigator list — do not dial.
DNC_NATIONAL_VIOLATIONOn the federal DNC registry and no consent on file.
REASSIGNED_NUMBERNumber may have been reassigned — re-verify consent.
TCPA_AI_VOICE_CONSENTAI-voice call requires express written consent — not on file.
QUIET_HOURSOutside the 8:00–21:00 local calling window at the number.
DISCONNECTEDNumber appears disconnected.
INVALID_NUMBERNot a valid E.164 phone number.
GATE_UNAVAILABLEA gate check failed or timed out — treated as DENY (fail closed).
REGISTRY_UNAVAILABLEA registry could not be reached — treated as DENY (fail closed).

5. Checks and data sources

  • Number validity & line type — E.164 validation, carrier, line type, disconnected status. Live carrier data via Telnyx when configured; otherwise cached/deterministic fallback.
  • Federal DNC — FTC National Do Not Call registry file, cached locally (authorized access; you are responsible for subscription/exemption rules).
  • Litigator screening — runs before DNC against your loaded litigator feed (vendor scrub file).
  • Reassigned numbers — FCC Reassigned Numbers Database pattern; requires the RNDB data file to be loaded, otherwise reported as unavailable (never silently skipped).
  • Calling hours — recipient-local 8:00–21:00 window via an area-code → IANA timezone map (US + Canada).
  • Consent recording — the gate records the consent you declare per request. It does not validate legal sufficiency.

See the live data-source receipts at GET /api/v1/registry-health or the status page.

6. Evidence records

Every gate request writes a hash-chained evidence record: request context (masked phone — last 4 digits only), checks performed, decision, reason, and timestamps. Altering any record breaks the hash chain and is detectable.

GET /api/v1/gate/audit/{evidence_id}   // retrieve one record
GET /api/v1/gate/audit/chain           // verify the full chain
GET /api/v1/gate/audit/export          // CSV export (paid plans)
GET /api/v1/gate/ticket/{id}           // review ticket for a paused decision

7. Error handling and fail-safe policy

Missing, timed-out, or unavailable upstream checks must never silently become allow. The default is fail-closed: an incomplete check yields DENY with GATE_UNAVAILABLE or REGISTRY_UNAVAILABLE. Treat any 5xx, timeout, or network error as “do not act” and retry later.

HTTP 400 phone_required      — malformed request
HTTP 429 rate_limited        — slow down; retry_after seconds
HTTP 429 quota_exceeded      — free monthly quota used; sign up for a key
HTTP 401/403                 — missing or invalid API key
5xx / timeout                — fail closed: do not dial

8. MCP server

The MCP endpoint at POST /api/mcp exposes the gate to any MCP-compatible agent client.

// claude_desktop_config.json / .mcp.json
{
  "mcpServers": {
    "verifyone": {
      "url": "https://app.verifyone.io/api/mcp"
    }
  }
}

Tool: verifyone_pre_dial_gate (alias of check_call_allowed; both work). Agent prompt rule:

Before placing any outbound call or sending an outbound message, call verifyone_pre_dial_gate. If the decision is block, do not proceed. If the decision is review, pause or transfer to a human. If the decision is allow, proceed and store the evidence_id.

Other tools: check_email_safety, validate_phone, verify_email, ip_lookup, bulk_verify, get_account. Live MCP responses use the same v1 ALLOW | DENY contract.

10. Platform examples

  • Vapi (native) — set your assistant's server URL to https://app.verifyone.io/api/webhooks/vapi; on DENY the call is aborted pre-connect.
  • Retell (native) — point the pre-call webhook at https://app.verifyone.io/api/webhooks/retell.
  • Bland — call the REST gate from a custom function before the call tool.
  • n8n / Make / Zapier — HTTP Request node before the dialer node; branch on the decision.
  • Any MCP client — use the verifyone_pre_dial_gate tool.

Full snippets on the homepage developer section and /for-platforms. Platforms without a native endpoint work through API / webhook / custom function.
