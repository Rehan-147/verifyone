The problem

AI agents can dial anyone.
That does not mean they should.

AI calling platforms make outbound automation easy, but compliance decisions often remain manual: consent records, DNC scrubbing, reassigned-number checks, permitted calling hours, opt-outs, and audit trails.

One bad campaign can create wasted dialer spend, customer complaints, client disputes, and regulatory exposure.

01

Consent is fragmented

Consent may exist in a CRM, form, spreadsheet, or agent memory — but the calling agent cannot reliably use it at dial time.

02

DNC and reassigned-number risk changes

A list that was clean last month may not be safe today. Numbers can be reassigned, disconnected, or added to suppression lists.

03

Agents need evidence

When a customer, client, or regulator asks why a call happened, “the agent decided” is not an answer. Teams need a sealed decision record.

The fix is not another dashboard — it is a decision your agent cannot skip. See how the gate works

One gate before every outbound action.

VerifyOne sits between your AI agent and the outbound action. It does not replace your dialer, CRM, or AI platform. It gives them a compliance decision layer.

What the gate checks

Every decision runs the same discipline.

Each outbound request is evaluated against the enabled checks. Risk scoring combines the results, and the decision includes the specific reason — not just a score.

Internal suppression

Opt-outs, complaints, and client-specific exclusion lists.

FTC Do Not Call

National DNC Registry status for the number being dialed.

FCC reassigned-number risk

Reassignment risk since the consent date, using an RNDB.

Carrier & line status

Disconnected, invalid, or high-risk line signals.

Litigator risk

Known serial-plaintiff and litigator-feed risk scores.

Consent & calling hours

Express-written vs. DNC-exempt consent and time-zone rules.

Credits vary by the checks enabled — the full gate is bundled at launch.

Three outcomes, no ambiguity

Your agent gets an explicit decision.

VerifyOne's decision API returns one of three outcomes for the pre-action gate. The decision includes a specific reason and an evidence ID — no black-box scores your team has to interpret.

allow

The action may proceed.

All enabled checks passed. Your agent continues, and the evidence ID is stored with the interaction.

Consent verified · DNC clear · calling hours OK

review

Pause or route to a human.

Something is inconclusive — for example, a reassigned-number check needs a human look. The agent should hold or escalate.

Reassignment risk inconclusive since consent date

block

The action should not happen.

A specific reason is returned — e.g. the number is on the National DNC Registry — and the evidence record captures why.

Number is on the National Do Not Call Registry

The live v1 API currently returns ALLOW | DENY. The three-outcome decision API is the roadmap shape — see /docs#decision-values.

Audit evidence

Every decision leaves evidence.

VerifyOne creates a tamper-evident audit record for each gate request. The record includes the request context, checks performed, decision, reason, timestamps, and evidence ID.

// Before placing any outbound call or sending an outbound message, call

Node.jsjavascript
const res = await fetch("https://your-verifyone-host/api/v1/gate/phone", {
  method: "POST",
  headers: {
    "Authorization": `Bearer ${process.env.VERIFYONE_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ phone: to, channel: "voice" }),
});
const gate = await res.json();

// Live v1 contract: ALLOW | DENY (review is on the roadmap — see /docs)
if (gate.decision !== "ALLOW") {
  console.log("skipped", to, gate.reason, gate.evidence_id);
  return; // fail closed
}
await dialer.placeCall(to, { evidence_id: gate.evidence_id });

FAQ

Frequently asked questions

What is VerifyOne?

VerifyOne is a pre-action compliance gate for AI calling and messaging agents. It returns an auditable decision before an agent dials or sends.

Does VerifyOne replace my dialer or AI platform?

No. It sits between your agent and the outbound action. Your platform still makes the call; VerifyOne helps decide whether the action should happen.

What decisions does VerifyOne return?

Allow, review, or block, with a reason and evidence ID. The live v1 API expresses this as ALLOW or DENY with a typed reason code — see the decision mapping in the docs.

Does VerifyOne guarantee I will not be fined?

No. VerifyOne provides compliance controls and audit evidence. It does not provide legal advice or guarantee regulatory outcomes.

Which countries are supported?

The initial focus is U.S. phone numbers. Canada, the U.K., Australia, and Ireland are expansion candidates. EU support is not generally available.

Does VerifyOne work with Vapi, Retell, or Bland?

VerifyOne is API- and MCP-first. It can be added to agent workflows through REST, webhooks, custom functions, or MCP where the platform supports them.

What happens if a data source is unavailable?

VerifyOne follows a fail-safe policy. Missing or unavailable checks do not silently become allow; they result in review or block according to the configured policy.
